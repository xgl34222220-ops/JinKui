# 金匮

只存在这台手机里的安全卡包与账本：

- **卡包**：登录密码、银行卡、U 卡（虚拟卡）、身份证、护照、社保卡、驾驶证、会员卡、门禁卡、Wi-Fi，以及任何你想自定义的卡片。
- **账本**（0.6.0 起）：现金、银行卡、支付宝、微信、信用卡等账户的收支与转账，月度汇总、分类统计和预算。和卡片放在同一个加密保险库里。

第一要务是安全，第二是顺手。

- 包名 `com.xiguli.jinkui`，minSdk 26，targetSdk 34
- 原生 Kotlin + Jetpack Compose（Material 3），ViewModel + Repository 分层，手动依赖注入
- 不申请任何联网权限

## 功能

- **首次启动**：设置主密码（带强度提示），随后可选开启生物识别与 PIN。
- **解锁**：主密码始终可用；生物识别；6–12 位 PIN（自绘数字键盘，不经过系统输入法）。
- **主页（牌堆）**：当前卡靠左完整展示，后面三张向右依次缩小、露出边缘并逐层融进底色；左右拖动连续翻牌，点后面露出的牌或左缘的窄边可以直接切过去。牌堆下方是当前卡的标题、标签和最要紧的几个字段，点一行即复制。点当前卡进详情，长按快速复制。
- **主页（列表，1.0 起默认）**：最上面是搜索框，下面是快速筛选（全部 / 置顶 / 两步验证 / 类型 / 标签）；置顶卡片是横向的小卡面，卡片满 6 张后出现“最近使用”；全部卡片放在一块分组里，每行是卡面缩略图、名称、主信息与次要信息（如“•••• 5972　有效期 08/29”），行尾一键复制最要紧的字段。右滑置顶，左滑复制账号，长按快速复制。“全部”标题上可直接切换排序；体检发现问题时顶部有一条提示。筛选“两步验证”时，行尾直接显示实时验证码，点一下复制。
- 两种视图都支持搜索（名称 / 标签 / 备注）和按类型或标签筛选，筛选后牌堆内容随之变化。
- **卡片**：11 种类型各有一套贴合实物的默认字段（见下表），新建时自动预填，可再增删改；字段类型有文本 / 密码 / 数字 / 日期 / 网址 / 电话，可标记为敏感；另有标签、卡面、备注、证件照片附件；可以把一张卡片复制一份当模板。旧卡片可在编辑页一键补上模板里缺的字段。
- **安全体检**：找出弱密码、在多张卡片里重复使用的密码、已过期和即将到期的卡片，并提醒还没有做过加密备份。全部在本机完成，不联网比对任何泄露库。
- **批量整理**：多选后置顶、加标签、删除；标签可以改名、合并、删除；可按名称、最近修改、最近使用、类型排序，首页同步生效。
- **搜索与筛选**：除名称、标签、备注外，非敏感字段的内容（账号、开户行等）也能搜到，敏感字段永远不参与搜索；可按置顶、类型、标签筛选。
- **到期提醒**：能识别常见写法的有效期（`08/29`、`2034-05-20`、`2020.01.01-2040.01.01` 等），90 天内到期或已过期时在列表和详情页标出。
- **卡面**：每种类型有自己的配色、纹理和标志物（见下表），也可以在编辑页改用纯色。
- **详情**：字段按该类型的重要程度排序，第一项放大；敏感字段默认打码，可逐个或一次全部显示；点整行即复制；长数字四位一组显示。
- **密码生成器**：长度 6–64，可选大小写、数字、符号，可避开易混字符；可直接填回正在编辑的字段。
- **历史密码**：敏感字段被修改时保留旧值（可在设置里关闭）。
- **两步验证码**（0.7.0 起）：在卡片编辑页“添加字段”里选“两步验证码”（登录密码卡片排在第一个），粘贴 `otpauth://totp/…` 链接或直接粘贴 Base32 密钥；支持 SHA1 / SHA256 / SHA512、6 或 8 位、30 或 60 秒（RFC 6238）。详情页显示实时验证码与倒计时，点一下复制验证码（同样标记为敏感、按设置自动清空剪贴板）。密钥和其他敏感字段一样加密保存、永远不参与搜索、不出现在卡面和“一键复制”里，详情页也不显示密钥本身；包含在加密备份里。0.8.0 起也可以点字段右侧的二维码图标，从相册 / 文件里选一张二维码截图，金匮在本机离线识别后填入（ZXing core）：只经系统选择器读这一张图片，不需要相机、存储或任何新权限，图片只在内存里解码、用完即清，不保存为附件。0.9.0 起也认 Google 身份验证器的批量导出码（`otpauth-migration`）：只有一个账号时直接填入，多个账号时打开预览。
- **从身份验证器导入**（0.9.0 起）：设置 → 两步验证码 → 从身份验证器导入，选一张“导出账号”二维码截图。金匮在本机解析其中的 protobuf 数据（自己按公开字段编号写的只读解析器，带长度与边界检查，不引入 protobuf 库），列出每个账号的发行方与账号名（不显示密钥与验证码），默认勾选可用且金匮里还没有的；HOTP、MD5 等不支持的账号逐条标出原因。导出码分成多张时会提示“第几张 / 共几张”，逐张导入即可。
- **设置**：自动锁定时间、剪贴板清空时间、浅色 / 深色 / 跟随系统、加密备份导出与导入、修改主密码、输错自毁开关、立即清空全部数据。

### 账本

1.1 起底部是悬浮的五个分区：账本、日历、卡包、统计、我的。账本首页的“添加一条新记账”直接打开记一笔；日历里可以给选中的那天补记。

- **账户**：现金、银行卡、支付宝、微信、信用卡、其他；银行卡 / 信用卡账户可以关联卡包里的一张银行卡。余额不单独保存，永远是“期初余额 + 全部收支 ± 转账”算出来的，改一笔、删一笔都不会对不上；信用卡欠款记为负数。有流水的账户不能删除，可以停用。
- **记一笔**：支出 / 收入 / 转账三种；底部面板自带数字键盘（不经过系统输入法），支持 `12.5+3-0.5` 这样的加减；可选分类（两级）、账户、日期与时间、备注和标签；“再记”保存后直接记下一笔。默认账户是这个分类上一次用的账户（从没记过就用最近一笔的账户）；账本首页的“快速记一笔”可以一点就带着常用分类打开；流水右滑或长按可以“再记一笔”。
- **金额**：一律以“分”为单位的整数保存与计算，不经过浮点数，不会出现 0.1 + 0.2 ≠ 0.3。
- **分类**：预置一套常用的两级分类（餐饮、交通、购物、居住、娱乐、医疗、学习、人情、家庭……；工资、奖金、理财收益、兼职副业、收红包、退款……），每个都有图标；可以新增、改名、换图标、隐藏。分类不会被删除，已有流水不会失去归属。
- **月度视图**：按天分组（日期头吸顶），每天显示当日收支；顶部是当月支出（数字滚动）、收入、结余与日均支出，设了预算时显示进度。停在本月时跨过月末会自动跳到新的月份。可按账户、分类（选一级分类时包含其子分类）筛选，也可以搜备注和标签。
- **统计**：月统计 / 年统计；汇总横幅与环比；柱状图（年统计 12 个月、月统计近 6 个月，柱顶标金额）；“收支热力”每日点阵；按一级分类的环形占比图与明细。图表用 Compose Canvas 自绘，没有引入图表库。
- **日历**：离线农历（1900–2100）、二十四节气、传统节日与主要公历节日，每天的收支小点，选中一天看当天流水、给这一天补记。
- **资产总览**：净资产、总资产 / 负资产、信用欠款与各账户余额，可一键隐藏金额。
- **预算**：每月总预算与分类预算，按月循环；显示已用、剩余、超支，以及本月剩余每天可用的额度。
- **周期记账**（0.7.0 起）：房租、工资、订阅这类固定收支设一次即可，每天 / 每周 / 每月 / 每年重复，可设记账时间、结束日期、暂停。每次解锁金匮、回到账本页时把到期的各期记上——不用后台任务、不联网。每月 31 日这类日期在小月落到月末，且不会越漂越早；开始日期早于今天时会补记至今的各期（每次最多 400 笔，剩下的下次接着补）。生成的流水 ID 由“规则 + 日期”决定，同一规则同一天只会有一笔，重复打开、两台手机互相导入备份都不会重复。改了开始日期或频率时从上一次已记的日期之后继续，不会重记。账户被停用或删除时规则暂停生成，删除规则不会删掉已经记下的流水。
- 所有计算（余额、汇总、分组、统计、预算）都在后台线程完成。

### 账本的数据保护

- 与卡片同一个 SQLCipher 数据库、同一把字段密钥：金额、备注、标签、账户名、分类名、预算金额都放在每条记录的 `data_enc` 里做字段级 AES-256-GCM，AAD 绑定到记录（`ledger:tx:<ID>` 等），挪到别的记录上无法解密；明文列只有 ID、类型、时间和关联 ID。周期记账规则（金额、账户、分类、频率、日期、进度）整条都在 `data_enc` 里，明文列只有 ID 与更新时间。
- 锁定时与卡片一样丢弃内存明文；锁定期间无法读写账本。
- 加密备份（`.jkbak`）同时包含卡片与账本（含周期记账规则与删除标记）；导入时账本按“本机没有的加入、两边都有保留更新时间较新的、不删除本机记录”合并，整批在一个事务里写入。
- 删除标记（0.9.0 起）：删除周期记账生成的流水或删除一条周期规则时，在同一个事务里记下它的 ID（`ledger_tombstones`，只有 ID、种类与删除时间，没有金额等内容）。补记周期流水时跳过这些 ID；导入备份时，本机或备份任一边标记过的流水 / 规则都不会加回来；备份里的标记一并记到本机，但本机仍存在的记录不受影响（导入永远不删除本机记录）。手动记的流水删除后不记标记，行为与卡片相同。
- “清空全部数据”与输错自毁同样会删除账本。

## 安全设计

### 密钥层级

```
主密码 ──PBKDF2-HMAC-SHA256（60 万次）──▶ 口令密钥
                                            │ AES-256-GCM
                                            ▼
                                       [口令信封] ──Keystore 主密钥 AES-256-GCM──▶ 落盘
                                            │
                                    保险库密钥 VK（随机 256 位，只在解锁期间存在于内存）
                                            │ HKDF-SHA256
                    ┌───────────────────────┼───────────────────────┐
              SQLCipher 库密钥           字段密钥                 附件密钥
```

- **Keystore 主密钥**：AES-256-GCM，不可导出，设备支持时放在 StrongBox。它不直接加密每个字段，而是包裹“口令信封”——每次读写字段和附件都走 Keystore 太慢，所以采用信封加密。
- 解开保险库需要同时具备**这台设备的 Keystore** 和**正确的主密码**。本机不保存任何口令哈希，口令是否正确由 GCM 认证标签判定。
- **生物识别**：另一把必须经强生物识别认证才能使用的 Keystore 密钥，用来封装 VK；系统里新增指纹或面容后自动失效，需用主密码重新开启。
- **PIN**：可选的应用内 PIN，同样是“PBKDF2 + Keystore”两层封装。它是便捷方式，强度低于主密码。

### 数据

- 数据库：SQLCipher 整库加密。
- 字段值、备注、历史密码、附件：入库 / 落盘前再做一层 AES-256-GCM，每段密文都绑定到所属的卡片与字段（AAD），挪到别处无法解密。
- 名称与标签只有 SQLCipher 这一层保护。
- 解锁后，卡片解密到内存供搜索与展示；锁定时先关闭数据库、再清零密钥，并销毁界面里的明文。密钥一旦清零即永久作废，锁定瞬间仍在进行的后台写入会直接失败，不会把用清零密钥算出的密文写进库。
- 导入备份时，替换一张卡片的“删旧 + 写新”在同一个数据库事务里完成；旧附件文件在提交成功后才删除，中途失败时本机原数据保持不变。

### 其他防护

| 项目 | 做法 |
| --- | --- |
| 离线 | Manifest 不声明 `INTERNET`，并显式移除依赖库可能带入的联网权限；CI 会检查 APK 的权限列表 |
| 自动锁定 | 切到后台后按设定时间锁定（立即 / 30 秒 / 1 分钟 / 5 分钟 / 10 分钟）；前台无操作同样锁定（最短 30 秒） |
| 防截屏 | 主窗口与所有对话框都带 `FLAG_SECURE`；最近任务列表不显示内容 |
| 剪贴板 | 复制的内容标记为敏感，默认 30 秒后清空；若期间已被别的应用复制的内容替换（且系统允许查看），不会误清用户自己的内容 |
| 输错自毁 | 默认开启：主密码或 PIN 连续输错 10 次，清空数据库、附件与全部密钥；第 3 次起有递增的冷却时间 |
| 备份 | 只导出用主密码加密的 `.jkbak` 文件（PBKDF2 + AES-256-GCM），没有任何明文导出；导入时先做完整性校验，再按更新时间合并 |
| 系统备份 | 关闭系统云备份与换机迁移 |

### 已知的边界

- 字符串在 JVM 堆里无法可靠清零：解锁期间，已解密的卡片内容存在于进程内存中。
- 剪贴板清空靠进程内计时。如果进程在到点前被系统回收，要到下次启动时才补清。
- 修改主密码只更换口令信封，不会重新加密数据库；此前导出的备份仍用当时的主密码。
- 冷却时间按系统时钟计算，改系统时间可以跳过冷却，但跳不过 10 次的自毁上限。
- 已 root 或已被攻破的设备不在防护范围内。

## 界面

### 设计系统（1.1 薄荷）

- **品牌色**：薄荷绿。`primary` 用于大块填充（主按钮、选中日期、统计横幅、分段选中段），浅色 `#3AA084`、深色 `#5FC4A6`；`accent` 是深一档的薄荷，用于浅底上的小字、线条图标与“收入”，浅色 `#23785F`（白底上 5.3:1）、深色 `#6FD0B2`；`accentSoft` / `hero` 是浅薄荷底（选中图标填充、头图卡）。支出红浅色 `#D1404A`、深色 `#FF8A84`。
- **中性色**：浅色页面底 `#F5F6F5`、卡片 `#FFFFFF`、浅灰 `#EEF1F0`；深色是深绿灰 `#0F1513 / #18201D / #222B28`。三级文字在三种底色上对比度 ≥ 4.5:1。
- **插画色**：`leaf / leafDeep / hill / flower` 只给自绘的叶子、远山、小花用，深浅两套。
- **数字字体**：`JkFonts.numeral`（Oxanium 500 / 600 / 700）。`JkType.amount*`、`date`、`digits*`、`cardNumber` 都用它；中文标题与正文仍是系统黑体，分区标题 `JkType.section` 18sp 粗体。
- **形状与间距**：卡片 18dp 圆角、无描边无投影；页面左右 16dp；按钮、筛选、分段为胶囊或 14dp 圆角；行高 ≥ 64dp，触控区 ≥ 48dp。
- **图标**：`ui/components/MintIcons.kt` 的 `MintIcon`（底栏、宫格、标题栏），分类与卡片字段仍用 Material Symbols Outlined。
- **插画**：`ui/components/Botanical.kt`（`BotanicalCard`、日历空状态 `EmptyCalendarArt`、“我的”字标 `AppGlyph`）。
- **底栏**：`ui/nav/TabBar.kt`。分区页面用 `LocalTabBarInset` 给悬浮栏让出底部空间。
- **动态取色**：设置里的“跟随壁纸取色”仍在（默认关闭），只替换品牌色一组。

### 设计系统（1.0）

1.0 的靛青设计已由 1.1 的薄荷设计取代，下面保留 1.0 的说明作为记录。


- **一个品牌色**：靛青（浅色 `#3E4FC1`、深色 `#9AA6FF`）用于主按钮、选中、置顶、底部栏“＋”、今天；浅底 `accentSoft` 用于选中标签、次要按钮与快捷复制按钮。收入 / 支出 / 转账三色只出现在账本里。
- **中性色**：浅色底 `#F5F6F8` / 卡片白 / 浅灰 `#EDEFF3`；深色底 `#0E1014` / 炭灰 `#171A20` / `#20242C`。三级文字在三种底色上对比度都 ≥ 4.5:1。
- **层次**：靠底色区分（页面底 → 分组 → 控件底），分组与面板不画描边、不用投影；描边只留给输入框与分隔线。
- **形状**：分组 20dp 圆角，同一组的行首尾圆角、中间直角；标签、按钮、搜索框、分段控件全部胶囊形；底部面板 28dp。
- **文字**：分区大标题 28sp 粗体；正文 15sp、辅助 13sp、说明 12sp；分组标题为 12sp 眉题“名称 · 数量”。金额、卡号、验证码用等宽数字。
- **间距**：4dp 网格，页面左右 20dp、分组内 16dp；行高 ≥ 64dp，触控区 ≥ 48dp。
- **图标**：Material Symbols Outlined，选中态用实心；分类图标放在圆形色底里。
- **动态取色**：设置 → 外观 →“跟随壁纸取色”（Android 12+，默认关闭），只换品牌色一组。
- **最常用操作的步数**（打开对应分区之后）：复制密码 / 卡号 1 次（行尾按钮）；复制账号 1 次（左滑）；复制验证码 2 次（“两步验证”筛选 → 点验证码）；记一笔 2 次点按加输金额（“快速记一笔”或“＋” → 金额 → 完成）。

### 卡包的视觉（0.9.0）

- 沿用 0.8.0 的设计令牌：卡号、证件号、打码的末四位、有效期一律用等宽数字（`JkType.digits*`、卡面上的 `JkType.cardNumber`），密码明文仍用等宽字体便于分辨 l / 1 / I。
- **银行品牌色**：银行卡用默认卡面时，从名称或“开户行”里认出常见银行（工行、建行、农行、中行、交行、招行、邮储、浦发、中信、光大、民生、兴业、平安、华夏、广发等），卡面底色带上该行主色，斜纹与金色芯片不变；列表缩略图、牌堆、详情、编辑预览一致。只是本地关键字匹配，不含任何银行标志图形；另选了颜色就按用户选的。
- **反馈**：可点的卡面与列表行按下轻微缩小（`rememberJkPress` / `pressScale`），长按有触感；复制成功是确认触感，复制图标变成对勾约 1.4 秒（`CopyFeedback` / `JkCopyButton`），提示文字仍在底部消息条。触感一律走系统“触摸反馈”设置，不需要震动权限。
- **详情页**：小节眉题与设置页同一种样式；敏感字段的字段名旁有一枚小锁，显示时明文淡入、轻轻上移。两步验证码换新时从下方滚入，圆环每秒匀速走完一格。
- **空状态**：匣子空着时是一叠卡片与锁孔，搜索 / 筛选无结果时是卡位与放大镜，全部用 Compose Canvas 绘制。
- 通用组件在 `ui/components/Feedback.kt`（按压、复制反馈、触感）与 `ui/components/BankBrand.kt`（银行品牌色）。

### 账本的视觉（0.8.0）

- **颜色令牌**：支出赭红、收入松绿、转账靛蓝，各有主色与浅底两档，深色模式单独调过对比度（`JkColors.expense / income / transfer` 及 `*Soft`）。列表里支出金额仍用正文色，只有图标底与图表用支出色，避免满屏发红。
- **数字**：金额一律用等宽数字（`JkType.amount*`，`tnum`），上下行对得齐；月度汇总、净资产、预算等总数变化时逐位上下滚动。
- **首页**：月度汇总卡（本月支出大字、收入 / 结余 / 日均三栏、预算进度条）；按天分组的吸顶日期头；每笔流水左边是按类型着色的分类图标底，右边右对齐的金额，分隔线从文字处开始。往下滚动后“记一笔”收成圆形按钮。
- **记一笔**：金额区按类型着色并显示当前分类；数字键按下有缩放、变色与键盘触感（跟随系统触感设置），“完成”是确认触感；分类块选中时按支出 / 收入着色。
- **统计**：环形图段间留固定缝、切换月份时顺时针展开；分类明细带图标与进度条；柱状图柱子圆头、虚线网格、选中月份有底带。图表色深色模式下整体提亮一档。
- **空状态**：账簿与铜钱（本月无记录）、小票与放大镜（筛选无结果）、虚线空环（统计无数据），全部用 Compose Canvas 绘制，不用图片资源。
- **动效**：克制为主——卡包 / 账本切换 180ms 淡入淡出，底部面板从下方滑入（关闭时立即移除），汇总卡尺寸变化平滑过渡，进度条与图表在数据变化时过渡。底部分区栏选中项有胶囊底与实心图标。
- 设计令牌在 `ui/theme/Theme.kt`，通用组件在 `ui/components/`，卡面在 `ui/components/CardFaces.kt`。

## 构建

需要 JDK 17 与 Android SDK（compileSdk 34）。

```bash
./gradlew testDebugUnitTest   # 单元测试 + Robolectric 界面测试（x86_64 上会把页面截图存到 app/build/outputs/ui-screenshots/）
./gradlew assembleDebug       # Debug APK：app/build/outputs/apk/debug/
```

Release 构建已开启 R8，需自行配置签名。

### 调试签名

Debug 构建固定使用仓库里的 `app/debug.jks`（PKCS12，别名与口令都是 `jinkui-debug`），这样每次 CI 产出的 Debug APK 签名一致，可以覆盖安装。**这把密钥是公开的，只用于 debug 构建，绝不能用来签 release。** 证书 SHA-256：

```
D1:0E:C6:11:74:54:4B:D8:5B:78:0D:9D:0A:03:4F:3B:12:7C:E5:9C:8D:3B:F2:C0:59:98:7E:D8:88:B9:01:0F
```

CI 会在构建后打印 Debug APK 的签名证书指纹，与上面不一致时直接失败。
